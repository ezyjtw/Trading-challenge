## Step 1.1 — Build and Start All Services

  # Build everything
  docker compose build

  # Start infrastructure first
  docker compose up -d redis postgres

  # Wait 5 seconds, then start all services
  docker compose up -d

  # Check all services are running
  docker compose ps

  # Expected: all services show "Up" status
  # If any service is restarting, check logs:
  docker compose logs <service-name> --tail 50

## Step 1.2 — Verify Market Data Flow

  # Watch market data stream
  docker compose logs market-data -f

  # You should see within 30 seconds:
  #   - WebSocket connected
  #   - Ticker updates for BTCUSDT, ETHUSDT
  #   - Funding rate polls completing

  # Verify data reaches Redis
  docker compose exec redis redis-cli XLEN market:data
  # Should return a number > 0 and growing

## Step 1.3 — Verify Strategy Engine Decisions

  # Watch strategy engine logs
  docker compose logs strategy-engine -f

  # Within 2 minutes you should see:
  #   - "strategy decision" log lines for each symbol
  #   - Decisions showing FUNDING_CARRY, BASIS_REVERSION, or HOLD
  #   - Regime classification (BULLISH/NEUTRAL/BEARISH)

  # Key things to verify:
  #   ✓ Basis tracker is recording samples (count increasing)
  #   ✓ Regime detector is classifying correctly
  #   ✓ Entry intents are being generated when conditions are met
  #   ✓ No panic/crash loops

## Step 1.4 — Verify Full Trade Cycle

  # Watch execution router
  docker compose logs execution-router -f

  # Wait for a trade intent to flow through:
  #   strategy-engine → trade:intents → challenge-daemon → trade:approved → execution-router

  # On testnet, check Bybit testnet dashboard:
  #   https://testnet.bybit.com → Positions
  #   You should see:
  #     - A spot BUY order filled
  #     - A perp SELL order filled
  #     - Delta-neutral position (long spot + short perp)

  # In strategy-engine logs, confirm:
  #   "strategy: position confirmed" — ConfirmEntry was called

## Step 1.5 — Verify Exit Cycle

  # If funding rate drops or goes negative on testnet, the engine should:
  #   1. Generate an exit intent
  #   2. Sell spot + buy perp (reverse of entry)
  #   3. Log "strategy: position closed"

  # To force-test exits: temporarily lower the funding threshold
  # by setting env var FUNDING_EXIT_THRESHOLD_RATE=0.001 and restart

## Step 1.6 — Verify Safety Trade

  # The safety trade fires at 22:00 UTC if no trade happened that day.
  # On testnet, verify by checking logs after 22:00 UTC:
  docker compose logs challenge-daemon -f
  # Should see safety trade intent generated

## Step 1.7 — Run for 24+ Hours

  # Let the system run for at least 24 hours on testnet.
  # Check the next morning:

  docker compose logs strategy-engine --since 24h | grep "strategy decision"
  docker compose logs execution-router --since 24h | grep "executing intent"
  docker compose logs challenge-daemon --since 24h | grep "trade recorded"

  # Verify:
  #   ✓ No crashes or restart loops (docker compose ps shows all "Up")
  #   ✓ At least 1 trade per day (safety trade at minimum)
  #   ✓ No drawdown breaches
  #   ✓ Positions are delta-neutral (check Bybit testnet)

  [ ] Redis streams are flowing (XLEN on each stream returns > 0)

## Step 3.1 — Daily Monitoring Routine

  # Every morning (pick a consistent time):

  # 1. Check service health
  docker compose ps

  # 2. Check for any warnings/errors overnight
  docker compose logs --since 12h | grep -i "error\|warn\|halt\|breach\|failed"

  # 3. Check strategy decisions
  docker compose logs strategy-engine --since 12h | grep "strategy decision"

  # 4. Check P&L
  docker compose logs challenge-daemon --since 12h | grep "trade recorded"

  # 5. Check trading day count
  docker compose logs challenge-daemon --since 12h | grep "trading_days"

  # 6. Log into Bybit and verify:
  #    - Positions match what the engine thinks it has
  #    - Equity is tracking correctly
  #    - No orphaned positions

## Step 3.2 — What to Expect

  Week 1-2:
    - System accumulates basis tracker data (first 30 minutes)
    - Regime detector needs 3+ days of funding data for accuracy
    - Expect mostly HOLD decisions initially (conservative by design)
    - Safety trades count trading days even when HOLD
    - Small funding carry trades when rates are favorable

  Week 3+:
    - Regime detector has enough data for accurate classification
    - Basis tracker z-scores become meaningful
    - More frequent funding carry entries on good days
    - Occasional basis reversion trades on spread spikes

  Typical day in positive funding environment:
    07:00 UTC - Strategy evaluates, enters funding carry (BTC+ETH)
    08:00 UTC - Funding payment collected (8h cycle)
    16:00 UTC - Second funding payment collected
    22:00 UTC - Safety trade check (already traded, skip)
    00:00 UTC - Third funding payment collected
    00:01 UTC - Daily reset, high-water mark updated

  Typical day in negative funding environment:
    07:00 UTC - Strategy evaluates, decides HOLD (negative rates)
    Throughout day - Monitors for basis reversion opportunities
    14:00 UTC - Basis z-score spikes to 2.5 → enters basis trade
    15:30 UTC - Basis converges, z-score drops to 0.3 → exits
    22:00 UTC - Safety trade if no trade yet today

## Step 3.3 — When to Intervene

  INTERVENE IMMEDIATELY if:
    - Any service shows "Restarting" in docker compose ps
    - Discord alert says "HEDGE FAILED"
    - Discord alert mentions "BREACH" or "HALTED"
    - Bybit shows positions that don't match engine state
    - Equity drops more than 2% in a single day

  HOW to intervene:
    # 1. Stop the execution router (prevents new trades)
    docker compose stop execution-router

    # 2. Check what happened
    docker compose logs execution-router --since 1h
    docker compose logs strategy-engine --since 1h

    # 3. Check Bybit positions manually
    #    If there are orphaned positions, close them manually on Bybit

    # 4. Fix the issue, restart
    docker compose up -d execution-router

  DO NOT INTERVENE for:
    - HOLD decisions (this is correct behavior when no opportunity exists)
    - Low daily profit (patience is the strategy)
    - Funding rates going negative (the engine handles this)
    - Basis z-score not triggering (thresholds are conservative by design)

# ============================================================================
# TROUBLESHOOTING
# ============================================================================

## Service won't start
  docker compose logs <service> --tail 50
  # Most common: Redis not ready yet. Restart the service.

## No trades happening
  # Check strategy engine decisions:
  docker compose logs strategy-engine --since 1h | grep "strategy decision"
  # If all HOLD: funding rates are too low and no basis opportunities.
  # This is CORRECT behavior. Wait for better conditions.

## Hedge failed alert
  # 1. Stop execution router immediately
  docker compose stop execution-router
  # 2. Check Bybit for orphaned positions
  # 3. Close any one-sided positions manually
  # 4. Check logs for root cause
  # 5. Restart when resolved

## Drawdown warning
  # Soft halt (3%): engine stops opening new positions automatically
  # Hard halt (4%): engine flattens optional positions
  # Breach (5%): CHALLENGE FAILED. Nothing to do but restart.
  # The system handles all of this. If you get a breach alert,
  # the challenge is over — don't trade further on that account.

## Stale market data
  docker compose restart market-data
  # WebSocket reconnects automatically but sometimes needs a nudge

## Redis full / OOM
  docker compose exec redis redis-cli FLUSHALL
  # Only do this if Redis is consuming too much memory
  # The system will rebuild state from exchange on next cycle
